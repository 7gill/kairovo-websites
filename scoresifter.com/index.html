§ Note from the developer — July 2026

I use ScoreSifter on my own library, and in its current form it doesn't go far enough. Matching from filenames alone means a file called Scan_047.pdf yields nothing useful — and a lot of real libraries look exactly like that.

The next version reads the page instead of the filename: title, composer, and work where a subtitle gives it. Key detection stays on the back burner until it can be trusted. Everything else is unchanged — free, offline, preview-then-commit, nothing renamed without your say-so.

§ 01   What it does

One folder in. Clean library out.

Everything ScoreSifter does happens on your machine. It never uploads your files or phones home.

01

Batch rename

Scan a folder, match every filename against the catalogue, propose new names. You review before anything changes.

02

Metadata in every file

Writes title, composer, work and key directly into each PDF — compatible with forScore, MobileSheets and other music PDF readers that parse standard metadata.

03

Template engine

Pick a preset or write your own. {title}, {composer}, {work}, {key} — with optional segments using [? … ?].

04

Reads the page

When a filename says nothing (Scan_047.pdf), ScoreSifter reads the title and composer from page one, scans included. It still cleans up IMSLP noise, shop codes and duplicate suffixes.

05

54k-piece catalogue

Art song, opera arias, lieder and musical theatre — embedded in the app. No internet required for the vast majority of lookups.

06

Online when it helps

When the catalogue doesn't know a piece, ScoreSifter asks MusicBrainz and Open Opus, sending only the title and composer. You decide whether to accept each result.

07

Undo log

Every rename run is logged with old → new pairs. Undo straight away, or later with Library ▸ Undo Last Renames, even after the app was closed.

08

Offline by design

No account. No cloud. Catalogue ships with the binary. Works on a plane, in a studio with no wifi, anywhere.

§ 02   How it works

Four steps. No surprises.

Every rename run is preview-then-commit. You see the exact change before it touches disk.

01

Point at a folder

Drag in a directory of PDFs. ScoreSifter walks it, parses every filename, and extracts title, composer and key signals.

02

Match the catalogue

Each file is checked against the embedded catalogue. High-confidence matches are flagged; anything uncertain is queued for your review.

03

Review and edit

Every proposed rename shows old vs new. Edit any field, override the template, skip individual files. Nothing changes until you say so.

04

Commit

ScoreSifter renames the approved files and writes metadata into every PDF, adding to the end of the file so nothing in it is lost. Undo puts the old names back, straight away or later.

§ 05   Questions

Frequently asked.

Q.01Does it change my files before I say so?+
No. Every run is preview-first. ScoreSifter shows the exact rename it proposes for every file. You review, edit, skip, and only then commit. Even after committing, Undo puts the old names back — straight away, or later with Library ▸ Undo Last Renames.
Q.02Where does the catalogue come from?+
It's KairovoData — a hand-curated database built from public-domain reference sources (art song corpora, opera catalogues, MusicBrainz snapshots) and cross-checked against primary scores. It ships embedded in the app — no network needed.
Q.03My file isn't in the catalogue. What happens?+
ScoreSifter reads page one for the title and composer, and asks MusicBrainz and Open Opus (sending only the title and composer). If there's still no match, you fill in the fields manually and the file gets renamed from your input, same as any other. Unverified matches are flagged so you can audit them later.
Q.04Does it work with forScore?+
Yes. ScoreSifter writes metadata into each PDF using the standard fields forScore reads — title, composer, work, and key signature. Import your renamed files into forScore, open any score's metadata panel, and tap Fetch. Everything populates. The full walkthrough is in the guide.
Q.05What platforms are supported?+
ScoreSifter 2 is a Mac app: macOS 14 Sonoma or later, on Apple silicon and Intel Macs (tested on Apple silicon). Reading page one with Apple Intelligence is optional and needs macOS 26 on a Mac that supports it.
Q.06Will it stay free?+
Yes. ScoreSifter is free forever. If a significantly new version ships years from now, the current version keeps working — any new one will be clearly labelled.
